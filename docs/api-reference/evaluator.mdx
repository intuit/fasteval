# Evaluator API Reference

The Evaluator runs metrics against evaluation inputs. You won't need it for most workflows — the decorator API handles things automatically — but it's there when you want direct control.

## Creating an Evaluator

```python
from fasteval import create_evaluator

evaluator = create_evaluator()
```

## Methods

### evaluate()

```python
async def evaluate(
    eval_input: EvalInput,
    metrics: List[MetricConfig]
) -> EvalResult
```

Runs the specified metrics on `eval_input` and returns an `EvalResult`.

## Example

```python
from fasteval import create_evaluator, EvalInput, MetricConfig

evaluator = create_evaluator()

result = await evaluator.evaluate(
    eval_input=EvalInput(
        actual_output="Paris",
        expected_output="Paris",
        input="What is the capital of France?"
    ),
    metrics=[
        MetricConfig(metric_type="correctness", threshold=0.7)
    ]
)

print(result.passed)  # True
print(result.metric_results[0].score)  # 0.95
```

## fe.evaluate() and fe.evaluate_async()

Score one output against named metrics without pytest or decorators: batch jobs, notebooks, scripts. Unlike `fe.score()`, a failing result is returned, not raised.

```python
import fasteval as fe

result = fe.evaluate(
    actual_output="Paris is the capital of France.",
    expected_output="Paris",
    input="What is the capital of France?",
    metrics=["correctness", "contains"],
)
print(result.passed, result.aggregate_score)
for m in result.metric_results:
    print(m.metric_name, m.score, m.reasoning)

# In async code
result = await fe.evaluate_async(actual_output=answer, expected_output=gold, metrics=["correctness"])
```

| Argument | Description |
|----------|-------------|
| `actual_output`, `expected_output` | The output and optional reference |
| `metrics` | Metric names (any `@fe.<name>` metric, including ones added with `fe.register_metric`), `MetricConfig` objects or `Metric` instances |
| `threshold` | Overrides every named metric's threshold (each otherwise keeps its decorator default) |
| `llm_client`, `model` | Judge for LLM metrics (default: the default provider) |
| `**fields` | Any other `EvalInput` field: `input`, `context`, `retrieval_context`, `history`, `tool_calls`, `metadata`, ... |

`fe.evaluate()` is synchronous; inside a running event loop use `await fe.evaluate_async(...)`.

## fe.register_metric()

Register a custom `Metric` subclass and get a decorator for it:

```python
fe.register_metric("legal_compliance", LegalComplianceMetric)

@fe.legal_compliance(jurisdiction="US", threshold=0.85)  # extra kwargs go to the constructor
def test_legal_response():
    fe.score(legal_assistant("Can I sue my landlord?"))
```

The name must be a Python identifier and can't shadow a built-in fasteval name (pass `overwrite=True` to replace a metric you registered earlier). `default_threshold=` sets the decorator's default. See [Custom Metrics](/docs/advanced/custom-metrics).
