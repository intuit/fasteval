# Configuration

fasteval picks up settings from several places: config files, code, or individual decorator parameters. Here's how they all fit together.

## Configuration Hierarchy

Settings resolve in this order (highest priority first):

![Configuration Hierarchy](docs/assets/configuration-hierarchy.svg)

1. **Per-metric decorator parameters**: `@fe.correctness(threshold=0.9, model="gpt-4o", llm_client=...)`
2. **The default judge set in code**: `fe.set_default_provider(...)`, usually in `conftest.py`
3. **`[tool.fasteval] judge_client`** in `pyproject.toml`: used when code hasn't set a default (see below)
4. **Environment variables**: `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` pick a default judge automatically

A metric's threshold has no global setting: each metric decorator takes its own `threshold=` (most default to 0.5; deterministic metrics such as `exact_match` default to 1.0). Run-level quality gates (`min_score`, `min_pass_rate`) live in [profiles](/docs/cli/profiles).

## Project Configuration (pyproject.toml)

`[tool.fasteval]` in `pyproject.toml` (or a standalone `fasteval.toml`) configures how evals are **run**: named [profiles](/docs/cli/profiles) for the `fasteval` CLI, the [tag](/docs/cli/tags) registry, and where [prompt judges](/docs/cli/prompt-judges) live. It keeps run settings out of your code and works the same way for every team member:

```toml
[tool.fasteval]
default_profile = "dev"
judges_dir = "judges"                       # prompt judge files
judge_client = "evals.judge_client:client"  # default LLM judge for evals and the UI playground

[tool.fasteval.tags]
smoke = "Fast sanity evals"
slow = "Long-running or expensive evals"

[tool.fasteval.profiles.dev]
paths = ["evals"]
tags = "not slow"

[tool.fasteval.profiles.ci]
extends = "dev"
tags = ""
review_prompts = false
headless = true
min_pass_rate = 0.9
```

| Key | Description |
|-----|-------------|
| `default_profile` | Profile `fasteval run` uses without `-p` |
| `tags` | Tag registry: `name = "description"` |
| `profiles.<name>` | Run settings: paths, tags, workers, reports, quality gates, environment. See [Profiles](/docs/cli/profiles#profile-keys) |
| `judges_dir` | Directory of prompt judge files. Default `judges` |
| `judge_client` | `"module:attribute"` of the project's default LLM judge. pytest runs and the UI playground use it unless code calls `fe.set_default_provider()` |

These are the only valid keys. The CLI rejects anything else with an error (and a "did you mean" suggestion). To choose the judge model project-wide, point `judge_client` at a client object; for anything else, configure the judge in code with `fe.set_default_provider()` or a metric's `model=` argument. See [LLM Setup](/docs/core-concepts/llm-setup).

## Programmatic Configuration

Configure the default LLM judge in code with `fe.set_default_provider()`. Any object with an async `invoke(messages)` method works, including `fe.OpenAIClient` or your own client for an internal gateway:

```python
import fasteval as fe

fe.set_default_provider(fe.OpenAIClient(model="gpt-4o-mini", temperature=0.0))
```

### Environment-Based Configuration

```python
import os
import fasteval as fe

if os.getenv("CI"):
    # Faster, cheaper judge in CI
    fe.set_default_provider(fe.OpenAIClient(model="gpt-4o-mini"))
else:
    # More accurate judge for local development
    fe.set_default_provider(fe.OpenAIClient(model="gpt-4o"))
```

With the CLI you can branch on the active profile instead: `fasteval run -p ci` sets `FASTEVAL_PROFILE=ci` for the run.

### conftest.py Configuration

`conftest.py` is the natural home, since pytest loads it before any eval runs:

```python
# conftest.py
import pytest
import fasteval as fe

fe.set_default_provider(fe.OpenAIClient(model="gpt-4o-mini"))

@pytest.fixture
def strict_judge():
    """A stricter judge for tests that ask for it."""
    return fe.OpenAIClient(model="gpt-4o", temperature=0)
```

An explicit `fe.set_default_provider()` always wins over `judge_client` in `pyproject.toml`.

## Per-Test Configuration

You can override defaults on any individual metric:

```python
@fe.correctness(
    threshold=0.9,        # Override default threshold
    model="gpt-4o",       # Override default model
)
def test_critical_functionality():
    response = my_agent(query)
    fe.score(response, expected)
```

Mix defaults and overrides freely:

```python
@fe.correctness(threshold=0.9)           # High threshold, default model
@fe.relevance()                          # All defaults
@fe.toxicity(model="gpt-4o-mini")        # Default threshold, fast model
def test_mixed_config():
    ...
```

## Configuration Options Reference

### Judge (LLM) Settings

| Setting | Where | Description |
|---------|-------|-------------|
| Default judge | `fe.set_default_provider(client)` | Client used by every LLM metric without its own |
| Project judge | `[tool.fasteval] judge_client = "module:attr"` | Default judge for runs and the UI playground when code hasn't set one |
| Per-metric model | `@fe.correctness(model="gpt-4o")` | Creates a client for that model (OpenAI `gpt-*`/`o1-*`/`o3-*`, Anthropic `claude*`) |
| Per-metric client | `@fe.correctness(llm_client=client)` | Any object with an async `invoke(messages)` |
| Temperature, API key | `fe.OpenAIClient(model=..., temperature=0.0, api_key=...)` | Set on the client; the key defaults to `OPENAI_API_KEY` |

### Threshold Settings

| Setting | Where | Description |
|---------|-------|-------------|
| Metric threshold | `@fe.<metric>(threshold=0.8)` | Pass mark for one metric (default 0.5; 1.0 for exact checks) |
| Run gates | profile `min_score`, `min_pass_rate` or `--min-score`, `--min-pass-rate` | Fail the whole run on low average score or pass rate |

### Run Settings

Parallelism (`workers`), test selection, reports, human-review prompts and environment variables are profile keys. See [Profiles](/docs/cli/profiles#profile-keys) and the [CLI reference](/docs/api-reference/cli).

## CI/CD Recommendations

In practice, we've found these CI defaults work well. Use a cheaper model, loosen the threshold a bit, and set a tight timeout so slow calls don't hang your pipeline:

```toml
# pyproject.toml: a CI profile for `fasteval run -p ci`

[tool.fasteval.profiles.ci]
review_prompts = false            # Never wait for human review
headless = true                   # No UI server; write .fasteval/report.html
workers = "auto"                  # Parallel workers (needs pytest-xdist)
min_pass_rate = 0.9               # Fail the run below 90% passing
env = { OPENAI_MODEL = "gpt-4o-mini" }   # Read by your conftest.py, if you choose
```

Pick the judge model for CI in code, for example in `conftest.py` based on `os.getenv("CI")` or `os.getenv("FASTEVAL_PROFILE")`. See [CI/CD Integration](/docs/cookbooks/ci-cd-setup) for complete pipelines.

```yaml
# GitHub Actions environment
env:
  OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
  FASTEVAL_NO_INTERACTIVE: "1"    # Skip human review prompts
```

## Multiple Configurations

If different suites need different judges, pass a client (or a model name) to the metrics that need it:

```python
# tests/test_smoke.py
import fasteval as fe

fast_judge = fe.OpenAIClient(model="gpt-4o-mini")

@fe.correctness(llm_client=fast_judge)
def test_basic_functionality():
    ...
```

`fe.set_default_provider()` is process-wide, and pytest loads every `conftest.py` before tests run, so it can't vary by directory. Per-metric `llm_client=` or `model=` is the way to use different judges in one run.
