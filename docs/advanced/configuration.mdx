# Configuration

fasteval picks up settings from several places: config files, code, or individual decorator parameters. Here's how they all fit together.

## Configuration Hierarchy

Settings resolve in this order (highest priority first):

![Configuration Hierarchy](docs/assets/configuration-hierarchy.svg)

1. **Per-metric decorator parameters** — `@fe.correctness(threshold=0.9)`
2. **Programmatic configuration** — `fe.configure(...)`
3. **pyproject.toml settings** — `[tool.fasteval]` (run settings: profiles, tags, judges; see below)
4. **Environment variables** — `OPENAI_API_KEY`, etc.

## Project Configuration (pyproject.toml)

`[tool.fasteval]` in `pyproject.toml` (or a standalone `fasteval.toml`) configures how evals are **run**: named [profiles](/docs/cli/profiles) for the `fasteval` CLI, the [tag](/docs/cli/tags) registry, and where [prompt judges](/docs/cli/prompt-judges) live. It keeps run settings out of your code and works the same way for every team member:

```toml
[tool.fasteval]
default_profile = "dev"
judges_dir = "judges"                       # prompt judge files
judge_client = "evals.judge_client:client"  # default LLM judge for evals and the UI playground

[tool.fasteval.tags]
smoke = "Fast sanity evals"
slow = "Long-running or expensive evals"

[tool.fasteval.profiles.dev]
paths = ["evals"]
tags = "not slow"

[tool.fasteval.profiles.ci]
extends = "dev"
tags = ""
review_prompts = false
headless = true
min_pass_rate = 0.9
```

| Key | Description |
|-----|-------------|
| `default_profile` | Profile `fasteval run` uses without `-p` |
| `tags` | Tag registry: `name = "description"` |
| `profiles.<name>` | Run settings: paths, tags, workers, reports, quality gates, environment. See [Profiles](/docs/cli/profiles#profile-keys) |
| `judges_dir` | Directory of prompt judge files. Default `judges` |
| `judge_client` | `"module:attribute"` of the project's default LLM judge. pytest runs use it unless code calls `fe.set_default_provider()`; the UI playground uses it too |

These are the only valid keys. The CLI rejects anything else with an error (and a "did you mean" suggestion). To choose the judge model project-wide, point `judge_client` at a client object; for anything else, configure the judge in code with `fe.set_default_provider()` or a metric's `model=` argument. See [LLM Setup](/docs/core-concepts/llm-setup).

## Programmatic Configuration

When you need runtime logic or conditional settings, `fe.configure()` does the job:

```python
import fasteval as fe

fe.configure(
    default_provider="openai",
    default_model="gpt-4o-mini",
    default_threshold=0.7,
)
```

### Environment-Based Configuration

```python
import os
import fasteval as fe

if os.getenv("CI"):
    # Faster, cheaper model in CI
    fe.configure(
        default_model="gpt-4o-mini",
        default_threshold=0.7,
    )
else:
    # More accurate model for local development
    fe.configure(
        default_model="gpt-4o",
        default_threshold=0.8,
    )
```

### conftest.py Configuration

For pytest-specific setup, fixtures are the natural home:

```python
# conftest.py
import pytest
import fasteval as fe
from fasteval import OpenAIClient

@pytest.fixture(scope="session", autouse=True)
def configure_fasteval():
    """Configure fasteval for all tests in this session."""
    fe.configure(
        default_model="gpt-4o-mini",
    )

@pytest.fixture
def strict_evaluator():
    """Fixture for tests that need stricter evaluation."""
    return OpenAIClient(model="gpt-4o", temperature=0)
```

## Per-Test Configuration

You can override defaults on any individual metric:

```python
@fe.correctness(
    threshold=0.9,        # Override default threshold
    model="gpt-4o",       # Override default model
)
def test_critical_functionality():
    response = my_agent(query)
    fe.score(response, expected)
```

Mix defaults and overrides freely:

```python
@fe.correctness(threshold=0.9)           # High threshold, default model
@fe.relevance()                          # All defaults
@fe.toxicity(model="gpt-4o-mini")        # Default threshold, fast model
def test_mixed_config():
    ...
```

## Configuration Options Reference

### LLM Provider Settings

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `default_provider` | str | "openai" | Provider name or custom client |
| `default_model` | str | "gpt-4o-mini" | Model to use for evaluation |
| `api_key` | str | None | API key (if not in environment) |
| `temperature` | float | 0.0 | LLM temperature (0 for deterministic) |

### Threshold Settings

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `default_threshold` | float | 0.7 | Default passing threshold |

### Performance Settings

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `max_concurrent_evals` | int | 5 | Parallel evaluation limit |
| `timeout` | int | 60 | Request timeout in seconds |

### Logging Settings

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `verbose` | bool | False | Detailed output |
| `log_level` | str | "WARNING" | Logging level |

## CI/CD Recommendations

In practice, we've found these CI defaults work well. Use a cheaper model, loosen the threshold a bit, and set a tight timeout so slow calls don't hang your pipeline:

```toml
# pyproject.toml: a CI profile for `fasteval run -p ci`

[tool.fasteval.profiles.ci]
review_prompts = false            # Never wait for human review
headless = true                   # No UI server; write .fasteval/report.html
workers = "auto"                  # Parallel workers (needs pytest-xdist)
min_pass_rate = 0.9               # Fail the run below 90% passing
env = { OPENAI_MODEL = "gpt-4o-mini" }   # Read by your conftest.py, if you choose
```

Pick the judge model for CI in code, for example in `conftest.py` based on `os.getenv("CI")` or `os.getenv("FASTEVAL_PROFILE")`. See [CI/CD Integration](/docs/cookbooks/ci-cd-setup) for complete pipelines.

```yaml
# GitHub Actions environment
env:
  OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
  FASTEVAL_NO_INTERACTIVE: "1"    # Skip human review prompts
```

## Multiple Configurations

If different test suites need different settings, use separate fixtures:

```python
# tests/conftest.py

@pytest.fixture
def fast_config():
    """Configuration for quick smoke tests."""
    fe.configure(model="gpt-4o-mini")

@pytest.fixture
def accurate_config():
    """Configuration for thorough evaluation."""
    fe.configure(model="gpt-4o")
```

```python
# tests/test_smoke.py
def test_basic_functionality(fast_config):
    ...

# tests/test_critical.py
def test_production_quality(accurate_config):
    ...
```
