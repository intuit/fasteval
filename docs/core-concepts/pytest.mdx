# Pytest Integration

fasteval works as a pytest plugin. You don't need to learn a new test runner—just write tests the way you already know.

> **Tip:** The [`fasteval` CLI](/docs/cli/overview) is a front end for exactly this plugin. `fasteval run` runs your evals with profiles, a live UI and run history, and prints the plain `pytest` command it runs. Everything on this page keeps working with `pytest` alone.

## How It Works

![Pytest Integration Flow](docs/assets/pytest-integration-flow.svg)

The plugin registers automatically when you `pip install fasteval-core`. No config, no extra setup.

## Running Tests

```bash
# Run all fasteval tests
pytest

# Verbose output (see individual metric scores)
pytest -v

# Run specific file
pytest tests/test_my_agent.py

# Run specific test
pytest tests/test_my_agent.py::test_qa_response

# Run tests matching a pattern
pytest -k "test_support"

# Stop on first failure
pytest -x

# Run in parallel (requires pytest-xdist)
pytest -n auto

# Run only fasteval evals, skipping plain unit tests
pytest --fe-only

# Select by tag (see Tags)
pytest -m smoke
pytest -m "rag and not slow"

# Every eval carries a `fasteval` marker
pytest -m fasteval
```

The same runs with the CLI are `fasteval run`, `fasteval run -t smoke` and `fasteval run -n auto`; see [Running Evals](/docs/cli/running-evals).

Under `pytest -n` (pytest-xdist), results from every worker are merged back into the main process, so `--fe-summary`, `--fe-output` reports and quality gates cover the whole run.

### Parametrized and Data-Driven Cases

`@pytest.mark.parametrize`, [`@fe.dataset`, `@fe.csv` and `@fe.jsonl`](/docs/core-concepts/data-sources) all produce one pytest test case per item. Result names keep the case id, so `test_faq[refund]` and `test_faq[hours]` are reported separately in the summary, in JSON and HTML reports, and in the UI.

## Understanding Output

A passing test shows scores above thresholds:

```
tests/test_agent.py::test_qa_response PASSED

Evaluation Results:
  ✓ correctness: 0.92 (threshold: 0.80)
  ✓ relevance: 0.88 (threshold: 0.70)
```

A failing test shows what went wrong:

```
tests/test_agent.py::test_support_flow FAILED

Evaluation Results:
  ✓ correctness: 0.85 (threshold: 0.80)
  ✗ toxicity: 0.72 (threshold: 0.95)
    Reasoning: Response contains dismissive language that may
    be perceived as unhelpful or rude.
```

### Exporting Results

You can export evaluation results to JSON or HTML, or print a summary table to the console:

```bash
# Export as JSON
pytest tests/ --fe-output json:results.json

# Export as HTML report
pytest tests/ --fe-output html:report.html

# Print a summary table after the run
pytest tests/ --fe-summary
```

For full details on output formats, custom reporters, and programmatic access, see [Output Collectors](/docs/advanced/output-collectors).

## Plugin Options

The plugin adds these options to `pytest`. The CLI uses the same options under the hood (shown in parentheses):

| Option | Description |
|--------|-------------|
| `--fe-only` | Run only fasteval evals and deselect other tests (default in `fasteval run`; `--all` turns it off) |
| `--fe-output TYPE:PATH` | Export results as `json:path` or `html:path`. Repeatable (`--json`, profile `outputs`) |
| `--fe-summary` | Print the summary table after the run (on by default in `fasteval run`) |
| `--fe-min-score X` | Fail the run if the average aggregate score is below `X`, 0 to 1 (`--min-score`) |
| `--fe-min-pass-rate X` | Fail the run if the eval pass rate is below `X`, 0 to 1 (`--min-pass-rate`) |
| `--fe-judge METRIC=JUDGE` | Swap a metric for a saved [prompt judge](/docs/cli/prompt-judges). Repeatable (`--judge`) |
| `--fe-inventory PATH` | Write a JSON inventory of collected evals: tags, metrics, thresholds, data source (`fasteval list`) |
| `--fe-events DIR` | Write a live JSONL event log of the run, used by the [local UI](/docs/cli/local-ui) |
| `--no-interactive` | Skip human-review prompts (`--ci`, profile `review_prompts = false`) |

An eval is a test that uses a metric, a data source or `@fe.human_review()`. The plugin marks each one with a `fasteval` marker during collection. `@fe.tag()` alone doesn't make a test an eval: `--fe-only` deselects a test that only has tags, while `pytest -m <tag>` still selects it.

Quality gates turn aggregate quality into a pass/fail signal for the whole run:

```bash
pytest --fe-min-pass-rate 0.9 --fe-min-score 0.75
```

A failed gate prints `FastEval gate failed: ...` and sets the exit status to 1, even if every test passed. If a run records no eval results, the gates aren't applied.

## Configuration

### Using pyproject.toml

`[tool.fasteval]` in `pyproject.toml` holds the tag registry and the CLI's [profiles](/docs/cli/profiles). The plugin reads the tag registry from it, so registered tags work with plain `pytest` too:

```toml
[tool.fasteval.tags]
smoke = "Fast sanity evals"
slow = "LLM-heavy evals for nightly runs"
```

Judge provider and model settings are not read from `pyproject.toml`; set them in code, as below.

### Using conftest.py

For programmatic configuration or test-scoped setup:

```python
# conftest.py
import pytest
import fasteval as fe
from fasteval import OpenAIClient

@pytest.fixture(scope="session", autouse=True)
def configure_fasteval():
    """Configure fasteval for all tests."""
    client = OpenAIClient(model="gpt-4o-mini")
    fe.set_default_provider(client)

@pytest.fixture
def strict_client():
    """A stricter evaluator for critical tests."""
    return OpenAIClient(model="gpt-4o", temperature=0)
```

### Environment-Based Configuration

You can use different settings for CI vs local development:

```python
# conftest.py
import os
import fasteval as fe

def pytest_configure(config):
    if os.getenv("CI"):
        # Faster model in CI
        fe.set_default_provider("openai", model="gpt-4o-mini")
    else:
        # More accurate model locally
        fe.set_default_provider("openai", model="gpt-4o")
```

## Fixtures

### Built-in Fixtures

```python
def test_with_evaluator(evaluator):
    """Access the underlying evaluator for advanced use cases."""
    from fasteval.models import EvalInput, MetricConfig

    result = await evaluator.evaluate(
        eval_input=EvalInput(
            actual_output="Paris is the capital",
            expected_output="Paris",
            input="What is the capital of France?"
        ),
        metrics=[MetricConfig(name="correctness", threshold=0.8)]
    )

    assert result.passed
```

### Custom Fixtures

Create fixtures for your specific testing needs:

```python
# conftest.py
import pytest

@pytest.fixture
def test_agent():
    """Fixture that provides your agent instance."""
    from my_app import Agent
    return Agent(model="gpt-4o")

@pytest.fixture
def sample_queries():
    """Common test queries."""
    return [
        "How do I reset my password?",
        "What are your business hours?",
        "Can I get a refund?",
    ]
```

```python
# test_agent.py
@fe.correctness(threshold=0.8)
def test_agent_responses(test_agent, sample_queries):
    for query in sample_queries:
        response = test_agent.answer(query)
        fe.score(response, expected="helpful response", input=query)
```

## CI/CD Integration

### GitHub Actions

```yaml
name: Evaluation Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Install dependencies
        run: pip install -e ".[test]"

      - name: Run evaluations
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        run: pytest tests/ -v --tb=short --fe-output json:results.json --fe-summary --fe-min-pass-rate 0.9

      - name: Upload results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: evaluation-results
          path: results.json
```

With the CLI, the same job is `fasteval run --ci --min-pass-rate 0.9 --json results.json`, and it also writes a self-contained HTML report to `.fasteval/report.html` that you can upload as an artifact. See [CI/CD Integration](/docs/cookbooks/ci-cd-setup).

### Separating Fast and Slow Tests

Use [tags](/docs/cli/tags) to split deterministic (fast) tests from LLM (slow) ones. `@fe.tag` names are pytest markers that fasteval registers for you:

```python
# test_agent.py
@fe.tag("slow")
@fe.correctness(threshold=0.8)
def test_llm_evaluation():
    ...

@fe.contains()  # Fast, no tag needed
def test_contains_disclaimer():
    ...
```

```bash
# Run only fast tests in CI
pytest -m "not slow"            # or: fasteval run -t "not slow"

# Run full suite nightly
pytest
```

A plain `@pytest.mark.slow` works too; register it in `[tool.fasteval.tags]` or with `config.addinivalue_line("markers", ...)` in `conftest.py` to avoid pytest's unknown-marker warning.

## Troubleshooting

### Tests Not Discovered

Make sure test files match `test_*.py` and functions start with `test_`:

```python
# Correct
def test_my_agent():
    ...

# Wrong - won't be discovered
def my_agent_test():
    ...
```

### Async Test Issues

You'll need `pytest-asyncio` for async tests:

```bash
pip install pytest-asyncio
```

```python
import pytest

@pytest.mark.asyncio
@fe.correctness(threshold=0.8)
async def test_async_agent():
    response = await my_async_agent("query")
    fe.score(response, "expected")
```

### Timeout Issues

LLM evaluations can take a few seconds. Bump the timeout if you're hitting limits:

```toml
# pyproject.toml
[tool.pytest.ini_options]
timeout = 60
```
